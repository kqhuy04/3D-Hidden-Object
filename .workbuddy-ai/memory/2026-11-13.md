# 2026-11-13

## Performance audit (read-only, user asked: no code changes, no quality loss)

Read the whole hot path. Findings, in priority order, with the numbers that made
them findings (measurements from GLB JSON chunks, not guesses):

- `frontier-town`: 2088 prims / **599 materials** / 327 skinned nodes / 429k tris.
  `office`: 1488 prims / **1047 materials** / 354k tris. `symphony-stagecraft`:
  1519 prims / 925 materials / **1.18M tris**. Materials are unique per prop, so
  draw calls ≈ visible prims and each one is a state change.
- **Off-heightfield landmine**: `WorldCollision.getGroundHeight` falls back to
  `raycastGround` (full-mesh `Raycaster`) and `moveCapsule` calls it 3×/frame
  (281, 296, 459) + `groundAt` from `slopeScale`. 6.2 ms per query measured
  before → 10–25 ms/frame on a reef/dock edge. Use `terrainHeight` + last-known.
- **Shadow world rebuild** (1423 draws / 372k tris) still lands in one frame every
  6 m walked (`ANCHOR_SNAP_XZ = 6`). Quality-neutral fix = scrolling strip.
- `InteractableSelector.update` can spend up to 10 full-scene rays in one frame
  (cache TTL 200 ms / 0.5 m, both expire together).
- `NpcCrowd.startLeg`: 12 attempts × 6 samples × `groundAt` = up to 648
  `supportHeight` sweeps in one frame, ~1×/s.
- Collision has **no spatial index over parts**: `supportHeight` × 9 probes,
  `collectContacts` × 4 per substep, `deepestContact`, `raycastSegment` all loop
  every part and every triangle of a part whose box contains the point.
- Found screen: full-viewport `backdrop-filter: blur(13px)` + second GL context
  while the game keeps rendering at full rate.
- `composite()` blits the whole shadow map every frame (erase movers) — scissor
  to the mover rects.
- 327 skinned props on frontier-town are static but still pay the skinning path.

## Batch 1 shipped (same day)

Measured first, and the measurement changed two conclusions:

- **The 6.2 ms raycast landmine is real but narrow.** `getGroundHeight` only
  falls back to `raycastGround` where `sampleHeightField` returns null *and* the
  ray still meets the mesh's bounding sphere — i.e. a band just outside the
  rasterised grid. Far-away probes cost 0.0005 ms (three early-outs on the
  sphere), which is why a naive measurement said "not a problem". At the real
  spot on `coral-reef`: **13.6–17 ms per query**, and the walk called it 4× a
  frame.
- **Only 10 of 21 maps have a terrain node at all.** `cozy-farm`, `office`,
  `nyc-city`, `symphony-stagecraft` and six others have no `-terrain`/`ground`
  node, so they have no heightfield and their ground is an ordinary collision
  part. On those maps the fallback returns 0 instantly and the whole issue is
  moot. `WorldCollision.terrainHeight` returning null is the tell.
- Per-frame cost of one `moveCapsule`: **0.456 ms** (`nyc-city`, 204 parts /
  89k tris), **0.881 ms** (`cozy-farm`, 480 parts / 183k tris). That is the
  batch-2 target and it is bigger than estimated — the 9-probe `supportHeight`
  over every part is the cost, not the raycast.

Changes: `groundNear` (heightfield → last-known) used by `moveCapsule` and
`groundAt`, exact `getGroundHeight` kept for spawn/placement; `RAYS_PER_FRAME=2`
in the selector with items always ray-tested and the rest taken on trust for a
frame; `TargetOutline.warm` + `FoundStage.warm` called from the loading screen;
`Game.render(force)` skips every other frame while the found screen is up
(`onWindowResize` passes `true`, or the buffer stays black); two per-frame
allocations removed (`PlayerController` step vector, `Mounts` saddle point, plus
`updateWorldMatrix(true,false)` instead of the whole subtree).

Dropped: the scissored shadow blit. `setScissor` is multiplied by the canvas
pixel ratio, not the render target's size, and the adaptive scaler changes that
ratio mid-round — the failure mode is a ghost shadow, silently.

Verified: typecheck clean, 118/118 tests, smoke on `nyc-city` + `coral-reef`
(console clean, 6 render calls → 3 drawn with the veil up). Prompt latency probe
showed no regression once the run-to-run noise was accounted for (baseline ran
twice: cannon 5/12 frame 7 both times).

## Batch 1 committed, batch 2 measured and shipped

Batch 1 is `c53e2c1` ("Stop paying for work the frame already had an answer to").

Batch 2 was two items, and only one of them was the one I expected.

**NPC leg search, time-sliced.** `startLeg` now spends one attempt per frame for
the whole crowd and keeps the remaining tries on the actor. Measured by driving
the crowd at a fixed 1/60 s delta with every actor forced to search on the same
frame (`tmp-npc-spike.mjs`): worst frame per search went from median 6.9 ms /
max 19.8 ms to median 1.3 ms / max 11.8 ms. The residual max is a GC pause. All
actors still travel 2–4 m per 14 s in the walking check, so the slice does not
starve anybody.

**Collision index — the first attempt was wrong, and the numbers said so.**
A triangle-level grid (0.25 m cells, CSR buckets per part) produced *identical*
answers (4 000 queries hashed on two maps) and was **slower**: `supportHeight`
48.5 → 67.6 µs on cozy-farm. Props are a metre or two across, so every triangle
of a prop lands in the same one or two cells; the bucket culled nothing and added
an indirection per triangle. Reverted in full.

What the same measurement did show: `boundsOnlyLoop` — just the 480-part bounds
test, no triangles — costs 14–21 µs, and `supportHeight` is called **five times
per `groundAt`** (centre + 4 ring probes). The cost is the broad phase, so the
broad phase is what got indexed: `gatherParts` buckets *parts* by footprint
(2 m cells), every hot query walks that list in ascending part order (so
`collectContacts` keeps the same contacts in the same order), and `rebakePart`
rebuilds the buckets because a swinging door has a new footprint.

- `groundAt`: 279 → 107 µs (cozy-farm), 171 → 33 µs (hospital)
- `moveCapsule`: 1.03 → 0.45 ms (cozy-farm), 0.385 → 0.135 ms (nyc-city)
- one NPC leg attempt: 1.13 → 0.41 ms (cozy-farm), 0.84 → 0.16 ms (hospital)
- five actors searching in the same frame: 68 → 25 ms (cozy-farm)

Verified bit-identical, twice: 4 000 hashed queries across `groundAt`,
`supportHeight`, `deepestContact`, `raycastSegment` on two maps, and a 800-step
`moveCapsule` trail (straight + spiral) including the stuck-frame count.

**Batch 3: nothing shipped, on purpose.** `tmp-frame-split.mjs` puts 37.7 of the
38.9 ms of per-frame subsystem time in `sun` on this harness — but the harness is
SwiftShader, so that number is software rasterisation, not the shadow pass a
player pays for. None of the three deferred items can be validated here: the
scrolling shadow map trades away the light-space reuse the whole split depends on
(and a bigger `ANCHOR_SNAP_XZ` is a quality cut, which is forbidden), the
architecture merge destroys the object identity picking and the shadow layers are
built on, and skinned→`Mesh` baking destroys the skeleton identity that
`NpcCrowd`, `Mounts` and `Interactions` all find people and props by. Shipping
any of them blind would be a diff that looks good and a game that regresses.

## Map 1 review — the lake was in the heightfield

User review of `campground-lake` (11 items) plus three control requests. Controls
shipped first: pointer lock with a drag fallback (Escape releases the cursor, left
click or Resume re-captures it), a bottom dialogue panel with a real photographed
portrait (`PortraitBooth` renders the speaker into a `WebGLRenderTarget` and frames
the head bone), crawl now drops the first-person lens (1.62 → 0.62 m), and
`Interactions.ts` is **deleted** — open/close/turn/push/light are gone, four verbs
were four too many.

The map-1 root cause was one line: **`campground-lake-terrain` contains both the
`ground` mesh and the `water` mesh**, and `findTerrainMeshes` sweeps the group. So
the lake surface went into the heightfield (the body stood *on* the water) and every
bed dredge moved the sheet down with the bed, which is why two previous attempts at
"make the water deep" changed nothing measurable. Fixed by filtering mesh names
inside `collect`.

Then: `buildWaterSurface` (the sheet is a surface, −4.58 … −0.63, not a level),
a beach-profile dredge (0 at the waterline, 0.5 m/m out, capped at 1.25), sheet
opacity 0.6, `settleProps` for craft / lily pads / reeds / people anchored on the
**lowest vertex**, `PROP_SHIFTS` for the creek footbridge (−0.32 m onto its banks),
`fence_3` (the kit suffixes repeated names — `fence` matched nothing, `removals: 0`),
and `STAIR_PART` widened to the deck family and matched up the ancestor chain.

Measured after: raft −4.12, skiff −4.15, pads −4.03 against a sheet at −4.03…−4.05;
backpacker feet exactly on the ground at −3.00; bridge underside −1.25 with both
banks at −0.93; 17 parts carry a step allowance where 0 did. tsc clean, 118 tests
pass, 4-map smoke has no console errors.

## Fishing minigame — built, calibrated, verified

Request: a Stardew-style fishing minigame on map 1's lake shore, with Polyfork's
`propped-fishing-rod` in the hand and Mixamo's `Fishing Idle` / `Fishing Cast`
driving it; five fish from Polyfork swimming with their own clips; XP that widens
the catch bar. Clean up the leftover `tmp-*` scratch.

Built: `src/data/fishing.ts` (all balance), `Storage` fishing record + `recordCatch`,
`WorldLoader.getWater()` with `depthAt` / `nearestOpenWater`, `InputController`
held-button state, `CameraController.setLookEnabled`, `CharacterAnimator` fishing
clips + measured phase constants + `scrubCast`, `FishingRod`, `FishSchool`,
`FishingMinigame` (DOM), `FishingSystem` (state machine), CSS, `Game` wiring.

**The rod was the hard part.** A first-pass tuning put the rod in the hand but
drove the tip 0.4 m underground at the top of the back swing — a 2.2 m rod rigid
to a hand at chest height has nowhere else to go. Solved with a modelled wrist
roll (`keepTipUp`) that rotates the rod about the grip past a limit. Two wrong
versions before it: clamping the handle axis instead of the tip direction (the
tip stayed under the grass), and taking the heading from the tip when the tip is
near-vertical (the rod swung out sideways). Worst tip height is now +0.79 m.

**Ordering bug worth remembering:** the wrist roll ran in `FishingSystem.update`,
which is called *before* the body is posed — so it corrected against last
frame's arm, 30° of error per frame at 0.1 s deltas. Split out into
`updateRod(delta)`, called from `Game.update` after `controller.poseOnly`.

Verified end-to-end by `tools/fishing-probe.mjs` on the real lake: shore found at
2.0 m, cast lands, bite after ~11 s, bar won 0.37 → 0.98, card "Landed / Koi /
1.4 kg / +14 XP", save has `level 1, xp 38, caught {grouper 2.4, koi 1.4}` and the
school drops 9 → 8. tsc clean, 118 tests pass.

Cleanup: all `tmp-*` deleted, plus tracked `flow-*.png` and the empty `dom.html`.
`tmp-chrome-profile` (515 MB) resisted deletion — the trash wrapper aborts on it;
it is gitignored and can be removed by hand.

## Round 2: the rod was the wrong shape of problem

Six follow-ups from the user. Four are done and measured; the rod took most of
the day.

**The rod is aimed, not inherited.** Two reports — "the rod stabs into the right
wrist at idle" and "at the end of the wind-up, before the forward swing, it
pierces the body" — were one bug: the rod was a child of the hand, so the wrist
carried it. The Mixamo cast rolls the wrist through 140°, which put the tip at
the sky at rest and 0.4 m under the terrain at the top of the back swing. Every
clamp on the inherited version failed (`keepTipUp`, a handle-axis clamp, a
heading read off a near-vertical tip). Replaced with an authored aim curve
(`ROD_AIM`, elevation + azimuth about the body's yaw) and
`FishingRod.aim(direction)`; only the *position* comes from the hands now.
`GRIP`, `ROD_TUNING`, `setTuning`, `keepTipUp` and `MIN_RISE` are all gone.

**Both hands on the cork needed a second measurement.** The idle clip puts the
hands 0.22 m apart *across* the shaft, not along it, so a rod welded to the right
hand passes 22 cm from the left one and the left hand grips nothing — which is
what "two hands on the rod" looked like it wasn't. `aim` now slides the holder to
the midpoint between the two hands every frame. And `GRIP.x` went 0.30 → 0.06:
everything behind the grip hangs out of the hand, and at the wind-up peak the
hand is beside the head, so 30 cm of butt was 30 cm through the chest.

**Measure, don't photograph.** A screenshot from one angle cannot answer "does
the rod go through the character" — the rod is behind the shoulder and the
character wears a hat the width of a table. `tools/rod-clearance.mjs` samples
every rod vertex against every bone segment, pose by pose. It set both numbers
above, and it is graduated into `tools/` because nothing else can answer that
question.

**Fishing is now four maps, sixteen fish.** `FISHING_SPOTS` names
`campground-lake`, `alpine-and-snow`, `countryside-railway` and `coral-reef`,
each with its own weight table over one global catalogue. Eleven new Polyfork
fish downloaded for the reef and the canal; the two crabs ship `Idle`/`Walk`/`Run`
and get `benthic: true` so they sit on the bed instead of hanging under the
surface. The school now loads only the current spot's roster, and places in two
rings — the reef is a 6 × 5 m pool and a 4…26 m ring put two fish in it.

**The catch card is the found-object card.** `FoundScreen.showObject` is the
general form of `show`; the fish is `FishSchool.displayClone`, turned a quarter
about Y (a fish is authored nose-first along +Z, straight at the card's camera).
`FoundStage.show(object, owns=false)` stops the stage freeing geometry the school
still needs.

**The catch log opens in the map, on F.** Sixteen 192 px PNGs rendered by
`tools/fish-thumbs.mjs` — a runtime render would be sixteen megabytes loaded on
the frame the player presses the key. Uncaught fish are the same picture with
`filter: brightness(0)`, so the two states can never disagree about which way a
fish faces. Names are printed in their rarity's ink: common, moss, rust, and a
new `--plum` for legendary.

Verified: tsc clean, 138 tests, build clean, `tools/fishing-probe.mjs` full trip
on the lake, and each of the four maps fished from a real shore point (school
9/9/4/9, `canFishHere` true, rod out). Log opens to 16 cells / "7 of 16" and
Escape returns to PLAYING. All `tmp-*` deleted.

## Round 4 — the Polyfork licence purge

Polyfork wrote in: the repo served 71 `.mjs` modules in `assets-source/kit/` and
71 more in `extracted_kit/`. Their November 2026 terms split a kit download in
two — **GLB meshes are CC BY 4.0, everything else is Polyfork License with no
standalone redistribution** — and a public repo handing out `kit.mjs` is exactly
that. The user's ask was to get them out of the public repo, history included.

**The purge.** `assets-source/` (60 MB) and `extracted_kit/` (41 MB) held 142
`.mjs`, 127 `.glb`, 8 `.json`, 4 `.md`, 4 `.txt`. Nothing in `src/` reads them;
maps come from `public/assets/maps/`. Added both to `.gitignore`, then
`git filter-branch -f --index-filter "git rm -r --cached --ignore-unmatch
assets-source extracted_kit" --prune-empty -- --all` — 17 commits rewritten,
662 tracked files → 520.

**The trap that makes filter-branch a lie on its own:** `refs/original/*`, the
`backup-before-purge` tag and the reflogs all still pin the old commits, so
`git log --all` keeps showing 285 kit paths and `gc` frees nothing. Dropped all
three refs, deleted the tag, `git reflog expire --expire=now --all`,
`git gc --prune=now --aggressive`. `.git` went 175 MB → 79 MB and the count
finally hit 0.

**A force-push is not a purge.** After `push --force-with-lease`, `master` 404'd
the files but `raw.githubusercontent.com/.../cf28d56.../kit.mjs` still returned
200 with 39,010 bytes: GitHub serves unreachable objects by SHA until it runs
its own gc. The token here is `read:user, repo, user:email, workflow` — no
`delete_repo`, so the deletion had to be the user's click. They deleted the repo
and made a fresh one; pushed the clean 20 commits to it and `PATCH`ed
`default_branch` back to `master` (new repos default to `main`). Now the old SHA
is a 422 "no commit found" and every kit URL is 404.

**Docs had been part of the problem.** `docs/ASSET_INVENTORY.md` listed the
kit's `.mjs` and manifests as if they shipped, and `TECHNICAL_DECISIONS.md`
claimed the kit is packaged into `public/assets/environment/`. Both corrected,
plus a `THIRD_PARTY_NOTICES.md` section naming what is deliberately absent — and
flagging `public/assets/anims/*.json` as the one Polyfork-licensed *data* type
that does ship, since keyframe tracks are not meshes.

Note for a future rebuild: `assets-source/` and `extracted_kit/` are gone from
disk too. Re-download the kit and run `node tools/prepare-maps.mjs` first.
